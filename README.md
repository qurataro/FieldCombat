## 1. 先に直した不具合（項目19）

前回の **項目10（スロット番号順の走査）が、効果音・死亡音・1UP が鳴らなくなる原因** でした。

- エンジンは「そのフレームで先に処理したスロットが APU チャンネルを取り、後のスロットはレジスタを書けない」作りです。つまり **処理順＝優先度** です。
- 空きスロットは 8→0 の順に割り当てられます。そのため、効果音の再生中に BGM が始まると、次の効果音が BGM より後のスロット（8番）に入ります。スロット番号順だと BGM が常に先にチャンネルを取り、その効果音は最後まで鳴りません。
- 元と同じ「ID の若い順」に戻しました。走査方法は「未処理で最小の ID を持つスロットを探す」形にしたので、最悪 81 回の比較で済みます（元の二重ループは最悪 288 回）。

再現テストの結果（効果音 → BGM 開始 → 効果音 の順に鳴らした場合）:

| | ID $0E | $10 | $12 | $13 |
|---|---|---|---|---|
| 前回版（項目10あり） | 鳴らない | 鳴らない | 鳴らない | 鳴らない |
| 今回版（項目19） | 鳴った | 鳴った | 鳴った | 鳴った |

項目18の「完全リセット」で症状が出にくくなっていましたが、根本原因はこちらです。

## 2. サウンドデータ形式（解析結果）

### サウンドID（`sub_D5ED_sound_engine_set_bit` に A で渡す番号）

| ID | ch | 用途（呼び出し元から推定） |
|---|---|---|
| $00-$02 | SQ1/SQ2/TRI | ポーズ時の無音化 |
| $03 | SQ1 | ポーズ音（項目14で未使用） |
| $04-$06 | SQ1/SQ2/TRI | ジングル（`sub_8A29`） |
| $07 | SQ1 | 効果音 |
| $08-$09 | SQ1/TRI | 1UP |
| $0A,$1A,$1B | SQ1/SQ2/TRI | 砦BGM（入るとき） |
| $0B,$1C,$1D | SQ1/SQ2/TRI | 砦BGM（2曲目） |
| $0C,$1E,$1F | SQ1/SQ2/TRI | 通常ステージBGM |
| $0D-$13,$17 | 各種 | 効果音 |
| $14-$16 | SQ1/SQ2/TRI | ジングル（`disable_music` の直後に呼ばれる） |
| $18-$19 | SQ1/TRI | ジングル |

ID が若いほど優先度が高く、同じチャンネルを取り合ったときに勝ちます。

### ストリーム形式（`tbl_D9AB` が各IDの先頭を指す）

```
ヘッダ4バイト: ch(1=SQ1 2=SQ2 3=TRI 4=NOISE), reg0($4000系), reg1(sweep), reg3(長さ/周期上位)
以降のコマンド:
  $00-$BF nn : 音符。上位4bit=音名(0=A,1=A#,2=B,3=C … B=G#), 下位4bit=オクターブ(右シフト量), nn=フレーム数
              (NOISE の場合はこのバイトをそのまま $400E に書く)
  $xF nn     : 周期が0になる → 休符として使われている
  $C0 nn     : レジスタを書き換えずに nn フレーム待つ（タイ／無音の待機）
  $F0        : 先頭から再スタート（ヘッダも読み直す）
  $F2 lo hi  : 指定アドレスへジャンプ（ループ）
  $F4 xx     : reg1(sweep) を変更
  $F6 xx     : reg0（デューティ・音量）を変更
  $FF        : 終了・スロット解放
```

- 音程テーブル `tbl_D991` は A2(110Hz) から始まる平均律の12音です。オクターブ番号は **C3 ≒ 131Hz** を基準にしています。
- **APU レジスタは音符の頭で1回だけ書かれます**。そのため、ソフトウェアによる音量エンベロープやビブラートはありません。音量の変化はハードウェアのエンベロープ（reg0 の bit4=0）だけです。

## 3. アーケード版に近づける手順

### ステップ1：アーケード版の音を数値で取り出す
アーケード版は AY-3-8910 ×2（矩形波6ch＋ノイズ）です。MAME（`sonson` ドライバ）で VGM を記録し、各チャンネルの音程・音長・音量の変化を取り出します。AY のクロックは MAME のドライバ定義で確認してください（1.5MHz 前後の想定）。

- VGM はご自身が所有する基板やROMから取ってください。
- VGM ファイルをいただければ、`sound_macros.inc` 形式に変換するツールを作ります。

### ステップ2：データだけで直す（バイト数が変わらない範囲。最初はここから）

| 改善点 | 方法 |
|---|---|
| 音色を AY に寄せる | AY は **デューティ50%** 固定です。いまは多くのパートが 25%（ヘッダ reg0=`$7F`）なので、`SQ_VOL(2,15)` = `$BF` にします。1バイトの変更で効果が最も大きい箇所です。 |
| 音の減衰 | `SQ_ENV(2,rate)` でハードウェアの減衰を使い、AY のエンベロープの「ポン」と減衰する感じに寄せます。bit5 が立っているとエンベロープがループするので注意してください。 |
| 音程・リズム | `out/sound_listing.txt` とアーケード版のノート列を並べ、音名とフレーム数を直します。音符の数が同じならサイズは変わりません。 |
| テンポ | フレーム数で決まります（例：砦BGMは 11/22 フレーム単位）。アーケード版の1拍の長さに合わせて調整します。 |

### ステップ3：エンジンを拡張する（容量が必要）
- **空き容量**：この環境のビルドで、項目19を入れた状態で **365バイト** です（仮の include を使った計測なので、実際の値はお手元のビルドで確認してください）。PRG 32KB のバンク1つにすべて入っている構成です。
- **ソフトウェア音量エンベロープ**：毎フレーム `$4000`/`$4004` を書き換える処理を足します。AY 風の減衰やトレモロが出せます。スロットごとに RAM が数バイト必要です。
- **ドラムパートの追加**：BGM はノイズチャンネルを使っていません。通常BGMの3パート目（$1F）は、三角波の短い音を打楽器代わりにしているだけで、ベースがありません。ノイズでドラムを鳴らし、三角波をベースに回すと、アーケード版の厚みに近づきます。ただし ID は $00-$1F の32個すべて使用済みなので、ID の拡張（スキャン回数とテーブルの拡張）が必要です。
- **ドライバの完全置き換え**（FamiStudio など）：再現度は最も高くなりますが、容量が足りないためマッパーの変更が前提になります。

## 4. 検証方法
- `tools/sim_sound.py`：ビルドした PRG（`$8000-$FFFF` の32KB）と ca65 のリスティングを渡すと、BGM と効果音を鳴らしたときの APU 書き込みとフレームごとのサイクル数を確認できます。
- 実機の音は Mesen の APU 表示やサウンドの録音で確認し、MAME 版とスペクトログラムで比べます。
